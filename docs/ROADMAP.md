# 开发路线图

## Phase 0：中央服务转向（当前）

- 重写产品、MVP、架构、安全、数据和 API 文档。
- 移除 `/music`、ffprobe、Chromaprint 和服务器本地 Library 依赖。
- 增加中央目录、客户端观测和解析请求迁移。
- 保留运营管理员登录和 Web 管理壳。

退出条件：服务端构建不依赖用户音乐目录，数据库能够表达第一个中央匹配闭环。

## Phase 1：客户端接入与曲目观测

- 运营者签发、查看和撤销客户端安装凭证。
- Bearer Token 认证、scope、最后使用时间和限流。
- 接收并校验单曲观测，不接受绝对路径或音频文件。
- 幂等创建解析请求并查询状态。
- 编写野人音乐接入契约。

退出条件：一个真实野人音乐实例可以提交一首曲目并得到持久请求 ID。

## Phase 2：中央目录与一个 Provider

- 规范化 Artist、Release、Recording 和 Track。
- 选择一个允许使用和缓存的 Provider。
- 实现超时、响应大小、限流、有限重试和错误分类。
- 保存不可变来源观测、TTL 和适配器版本。
- 实现缓存命中、负缓存和并发请求合并。

退出条件：缓存命中不访问上游，未命中只产生一次受控 Provider 请求。

## Phase 3：匹配与候选

- 标题、歌手、专辑、时长、曲号和版本关键词评分。
- 专辑上下文、字段证据和关键冲突。
- 返回有序候选和字段级 Tag Patch。
- 建立中文流行、完整专辑和混乱散曲样本报告。

退出条件：野人音乐能够展示候选并解释推荐原因。

## Phase 4：审核回报与发布

- 接收接受、拒绝和本地写回结果。
- 运营端显示客户端、任务、Provider 和缓存健康度。
- 数据保留、删除、备份、恢复和审计。
- 反向代理、HTTPS、amd64/arm64 镜像和发布清单。

退出条件：满足 MVP 验收标准并完成一个真实 NAS 闭环。

## Phase 5：规模与质量

- MusicBrainz Dump 等开放数据集导入。
- 第二 Provider 和跨来源证据。
- PostgreSQL、独立 Worker、配额和多节点。
- P1 已提供公开账户、设备授权、月配额与手动订阅控制面；自动支付商集成仍需商业与合规需求明确后评估。
